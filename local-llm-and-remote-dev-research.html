1. Can this machine run local LLMs for coding?

Verdict: partially feasible. A fanless MacBook Air M4 with 24 GB unified memory can run only ~9B–26B-class models, serially, and only as a supervised / assistive tool — not a replacement for a frontier cloud coding agent.

Bottlenecks

  1. TTFT, not decode: prefill ~330–630 tok/s, bound by the 10-core GPU. A 4.5k-token prompt = ~7 s to first token, paid every agentic turn. M4 Pro / Max have 16–40 GPU cores — this is where the Air is weak.
  2. Quality gap: best local 27B ~86.0% SWE-bench Verified vs Claude Opus 5 at 97.0% (an 11-point gap); Qwen3.6-27B 77.2% vs 80.9. Documented local weaknesses: ~12% JSON tool-call format errors vs ~0.5% for Claude; long-context drift past ~14K tokens; losses on multi-file reasoning and long-horizon autonomous runs. Cloud streams 30–60+ tok/s vs 5–8 tok/s for the best local 27B here (~5–10× slower).

Recommended setups (ranked)

  1. Ollama + gpt-oss:20b — lowest friction; MLX by default on Apple Silicon; OpenAI-compatible; agent launch built in.
  2. Homebrew Python + mlx-lm / mlx_lm.server — Apple’s own stack; fastest decode (~46 tok/s gpt-oss-20b); continuous batching; needs a Python upgrade first.
  3. LM Studio or raw llama-server — LM Studio for comparing quants; llama-server for GGUF portability, quantized KV cache and FIM completion. LM Studio’s Electron overhead hurts at 24 GB.

Caveats & verdict

  • Fanless chassis throttles under sustained load.
  • Battery inference is slow and draining; one resident model at a time (27B + 9B will not both fit).
  • Neovim is the only editor-plugin surface (options unverified).
  • Verdict: worth doing as a hybrid — local for high-volume simple/private work, cloud for architecture and hard reasoning. Not for whole-repo context or unattended loops.

**Partially feasible.** Workable as a supervised/assistive coding tool in a narrow
band (~9B-26B class models). NOT feasible as a replacement for a frontier cloud
coding agent.

## DERIVED REQUIREMENT: TTFT BUDGET (the real bottleneck)
- Prefill on this chip: **~330-630 tok/s, bound by the 10-core GPU** (not bandwidth,
  not engine choice). M4 Pro/Max have 16-40 GPU cores.
- 4.5k-token prompt = **~7 s time-to-first-token**, paid every agentic turn.
- Specs must budget TTFT per prompt size, not just decode tok/s.

## TECHNICAL CONSTRAINTS
- Fanless chassis: sustained generation thermally throttles; quoted tok/s are cold-start.
- Battery operation is both slow and fast-draining.
- Expect ±15% variance on all tok/s figures by prompt length / context / build.

## QUALITY vs CLOUD (coding)
- Best local 27B (Qwen3.8-27B): **86.0% SWE-bench Verified** vs Claude Opus 5 **97.0%** (11-pt gap).
- Qwen3.6-27B: 77.2% vs 80.9 (Claude 4.5 Opus).
- Documented local weaknesses: ~12% JSON tool-call format errors vs ~0.5% for Claude
  (one reported measurement); long-context drift past ~14K tokens; clear losses on
  multi-file reasoning, novel architecture design, long-horizon autonomous runs.
- Cloud streams 30-60+ tok/s vs 5-8 tok/s for the best local 27B here (~5-10x slower).

## RECOMMENDED SETUPS (ranked)
1. **Ollama (brew) + a 20-26B MoE (`gpt-oss:20b`).** Lowest setup cost. Ollama 0.40.1
   runs MLX by default on Apple Silicon, exposes an OpenAI-compatible `/v1` endpoint,
   and `ollama launch claude --model ...` wires an agent directly.
2. **Homebrew Python + `mlx-lm` / `mlx_lm.server`.** Apple's own WWDC26-documented
   stack; fastest measured decode on this chip class; continuous batching for
   subagents. Costs one prerequisite install.
3. **LM Studio (GUI discovery) or raw `llama-server` (GGUF).** LM Studio for comparing
   quantizations; `llama-server` for GGUF portability, quantized KV cache
   (`-ctk q4_0 -ctv q4_0`), or the FIM `/completion` endpoint for inline autocomplete.
   LM Studio's Electron-class memory overhead is a real cost at 24 GB.

## CONTRADICTIONS FOUND
- Several April-2026 sources claim Ollama's MLX path requires 32 GB+ and falls back to
  llama.cpp below that. Ollama's own v0.40.0 notes (Sept 2026) say MLX is the default
  on Apple Silicon with no stated memory minimum. Treat the 32 GB claim as superseded;
  **verify empirically after install** (check `~/.ollama/logs/server.log`).

## RISKS THAT BELONG IN THE SPEC
- Thermal throttling on a fanless chassis under sustained load.
- Battery operation degrades both speed and battery life.
- RAM ceiling forces a single-resident-model design.
- TTFT scales with prompt size — large repo context is expensive per turn.
- Local tool-calling is unreliable enough that autonomous unsupervised agent loops
  must be explicitly out of scope; tool calls must be gated with a human in the loop.
- Python 3.9.6 must be replaced before any MLX path works.

## OPEN QUESTIONS FOR SPECIFIER
- Which Neovim plugin will drive the local endpoint? (No VS Code/Cursor/Zed installed,
  so editor-plugin options narrow to Neovim.) Plugin landscape UNVERIFIED — needs its
  own research pass before a spec commits to one.
- Should the spec cover inline autocomplete (small model + FIM) in addition to chat/agent?
  They cannot be resident simultaneously at 24 GB.
- Is the goal a full local replacement or a hybrid (local for volume, cloud for
  architecture/hard reasoning)? The latter is the better-supported design.

## SUGGESTED ACCEPTANCE CRITERIA (evidence-backed, measurable on this machine)
- On AC power with a fresh boot, the chosen model completes a 200-token generation
  within a stated tok/s band measured by `ollama ps` / the server's own counter.
- Peak RSS stays under ~16 GiB with a browser, an editor, and the runtime resident.
- Time-to-first-token for a stated prompt size (e.g. 4k tokens) is measured and
  recorded, not estimated.
- A local coding task runs end-to-end without OOM, swap pressure, or thermal
  throttling warnings in `pmset -g therm` / `memory_pressure`.
- The workflow degrades gracefully when a tool call fails format validation.

## NOT IN SCOPE
- Any model above ~30B parameters.
- Hardware upgrade (M4 Pro/Max would materially improve TTFT and capacity — name it,
  do not spec it).
- Autonomous unsupervised coding agents.

## STATE
**ready for spec** — hardware evidence verified; remaining unknowns are implementable
decisions, not blockers.

2. Home server vs VPS vs cloud API — where self-hosting makes sense

Headline: the crossover is ~$150–200/mo of Sonnet-class API spend (~40–60M tokens/mo). Below that, cloud wins — often 10–100×. Above team-scale utilization (~400 h/mo), owning saves 60–90%. A 2026 DRAM/GDDR shortage inflated every high-memory machine 25–75% YoY — the dominant fact.

Cost reality (Oct 2026)

  • Cheap API tier: Claude Haiku 5.5 ~$0.18/Mtok blended; GPT-5.6 Luna ~$0.40/Mtok; DeepSeek V4.1 Flash off-peak ~$0.24/Mtok. Self-hosting basically never beats these below ~100–200M tokens/mo.

Crossover points

  • 70B-Q4 local vs Sonnet-class API ($3.60/Mtok) breaks even at ~100 h/mo on a 5090 or M5 Ultra; vs Opus-class ($7.20/Mtok) at ~50 h/mo (~20M tokens); vs the cheap tier, never below ~200M tokens/mo.
  • Owning a 5090 vs renting it (active-only billing) only wins above ~350–400 h/mo sustained.
  • Monthly ownership of a 5090 box is ~$150–210/mo all-in — about the same as $150–200/mo of Sonnet-class API spend.

Scenarios

  • Light personal use (≤30M tokens/mo): cloud only. Haiku ~$5/mo vs a mini at $37/mo amortized.
  • Heavy solo dev (40–160M tokens/mo, $150–600/mo API): a 5090 box or M5 Ultra breaks even at 50–100 h/mo, then saves $100–450/mo if a local 70B Q4 is good enough.
  • Small team (0.2–1.5B tokens/mo): owning clearly wins ($0.20–1.0/Mtok vs $3.60).

Hidden costs

  • Quality gap: local 70B Q4 is ~Sonnet-4-class, a full generation behind Opus 5.5 / GPT-5.6. Comparing $/token across capability flatters local hardware.
  • API deflation vs hardware inflation: Opus went $15/$75 → $4/$20 in a year while machines sit at a memory-price peak — the break-even moves against self-hosting every quarter.

Recommendation (ranked)

  1. Default: cloud APIs routed to the cheap tier.
  2. First local box if desired: Mac mini M6 32 GB (~$1,499). Silent, ~45 W, breaks even vs Sonnet at ~100 h/mo. Buy for privacy / offline / always-on, not price. ($1,299 is the 24 GB config.)
  3. 70B-class at home: RTX 5090 box only near MSRP; dual used 3090s are cheaper per token but noisy and risky.
  4. Rent, don’t own, for batch / spiky work.
  5. Skip DGX Spark and Strix Halo for token economics.

Best architecture at this scale: cloud API default + optional Mac mini for privacy/offline + occasional spot GPU for batch.

# Spec input: Self-hosted LLM economics (Oct 2026) — decisions, thresholds, constraints

## Decisions (evidence-backed)
1. **2026 memory crunch is the dominant fact.** All high-RAM machines are priced 25–75% above 2025: Mac mini M6 base $899 (M4 was $599), Mac Studio M5 Max $2,499/M5 Ultra $5,499, DGX Spark 128GB $6,950 (launched $3,999), Strix Halo 128GB ~$3,299 (launched ~$1,499), RTX 5090 street ~$4,700 (MSRP $1,999). Any spec must not reuse 2024–25 price assumptions.
2. **Cloud API prices collapsed in 2026.** Cheap tier $0.10–0.50/Mtok (Claude Haiku 5.5 $0.10/$0.50; GPT-5.6 Luna $0.20/$1.20; Gemini 3.8 Flash $0.75/$3.75 intro). Mid tier: Sonnet 5.5 $2/$10, Gemini 3.1 Pro $2/$12, DeepSeek V4 Pro off-peak $0.66/$1.98. Frontier: Opus 5.5 $4/$20 (was $15/$75 in 2025), GPT-5.6 Sol $4/$20, Fable 5.1 $10/$50. Prompt caching = 90% input discount; Batch = 50% off both.
3. **Break-even math (3-yr amortization, $0.1834/kWh EIA Oct-2026, 4:1 input:output, idle power 24/7, ops time excluded):**
   - Self-hosting a 70B-Q4-class model beats Sonnet-5.5-class API spend ($3.60/Mtok blended) above **~50–100 h/mo active use (~20–45M total tokens/mo)** on a 5090 (~$4,700) or M5 Ultra ($5,499); beats Opus-5.5-class ($7.20/Mtok) above **~50 h/mo (~20M tokens)**.
   - Self-hosting **never** beats the cheap API tier ($0.18–0.40/Mtok) below ~100–200M tokens/mo.
   - Owning a 5090 beats *renting* a 5090 (Vast $0.37–0.70/hr, active-only billing) only above **~350–400 h/mo sustained utilization**. Rental is $1.21/Mtok (70B, single stream) or $0.62/Mtok (32B).
   - Rented H100 via vLLM batch serving ≈ $0.10/Mtok total tokens — best marginal compute for batch jobs, no capex.
   - Monthly ownership cost framing: 5090 box ≈ $150–210/mo all-in ≈ same as $150–200/mo of Sonnet-class API spend. **If current API bill < $150/mo or usage < 40M tokens/mo, nothing else is cheaper.**
4. **Quality caveat that must be stated in any plan:** local 70B Q4 ≈ Sonnet-4-class, roughly a full generation behind Opus 5.5/GPT-5.6. $/token comparisons across unequal capability flatter self-hosting. Local 8–27B is cheaper than cheap-tier APIs at high utilization but far weaker than Sonnet 5.5.
5. **Ranked recommendation:**
   1. Default = cloud API, routed to cheap tier for routine work (no purchase).
   2. First local box if desired: **Mac mini M6 32GB, $1,299** — break-even vs Sonnet API ~100 h/mo at 27–30B models; buy for privacy/offline/always-on, not price. 170 GB/s, ~45W, silent.
   3. 70B at home: RTX 5090 box (~$5,500 all-in) only near MSRP; dual used 3090 (~$1,700) has better token economics but noise/heat/warranty risk.
   4. 120B+ MoE open models: only Mac Studio M5 Ultra ($5,499 base 96GB; 512GB late Oct 2026) fits them; capacity purchase, not speed.
   5. Skip DGX Spark ($4,999–6,950, ~3–7 tok/s on 70B) and Strix Halo ($3,300, ~5.5 tok/s) for token economics — bandwidth-starved at 2026 prices.
   6. Rent for batch/spiky (Vast spot, RunPod H100 batched, Hetzner GEX44 $211/mo flat for EU-resident 24/7 small workloads). Fly.io GPUs deprecated July 31 2026 — do not specify.
   7. Recommended architecture at user's scale: API default + optional $1,299 M6 mini for privacy/offline + spot rental for batch.

## Derived requirements / constraints for the spec
- Any cost model in the spec must use **$0.1834/kWh**, not $0.15, and 2026 hardware prices, and must separate "verified vendor price" from "street/secondary estimate."
- Break-even claims must state: amortization period (3 yr), utilization (active h/mo), token mix (4:1 input:output), and which API tier is the comparator.
- If the spec involves purchase: flag DRAM-peak depreciation risk (25–75% price inflation may reverse), consumer-GPU EULA/warranty limits, home power/network reliability, and ops burden (1–4 h/mo, often exceeding savings for solo users).
- If the spec involves rented GPU: flag preemption (Vast community), no-SLA, data-residency/geography randomness, and serverless premium above ~50% utilization (Modal ~$3.95/hr effective H100).
- TTFT note for spec of local serving: even unified-memory boxes pay ~5–7s TTFT on ~4.5k-token prompts (DGX Spark 803 tok/s prefill; Apple similar); prefill speed specs belong in latency requirements.

## Suggested acceptance criteria
- Given a stated monthly token volume and utilization, verify the chosen option's $/Mtok against the stated API comparator (e.g., 5090 @70B: $3.66/Mtok at 100 h/mo vs Sonnet $3.60).
- Decision thresholds documented: <40M tokens/mo → cloud only; 40–200M → hybrid or single 5090/M5 Ultra if non-frontier quality acceptable; >400 h/mo sustained → own hardware or batched H100 rental.
- All prices cite source and date; volatile items (5090 street, used 3090, Vast spot) marked as estimates with ranges.
- Quality gate: local model tier explicitly classified vs frontier API (e.g., "70B Q4 ≈ Sonnet-4-class, not Opus 5.5").

- Tolerance for a 25–75%-inflated purchase price that may depreciate when DRAM supply recovers?
- Which data, if any, cannot leave the network (drives the privacy case independent of cost)?

3. Always-on box to code on remotely (run OpenCode / terminal clients)

Best choice: a cheap VPS + Tailscale + mosh/tmux + OpenCode client/server mode. ~$5–10/mo, 10–25 ms latency, zero open ports, survives laptop sleep. A home Mac mini only makes sense if you also want a 24/7 local model. OpenCode is natively client/server (opencode serve + opencode attach + opencode web), so a thin laptop + a cheap box is the whole design.

Option classes

  • Cloud VPS (best value): Contabo Cloud VPS 10 (3C/8G/75G) ~$4.9/mo; Contabo VPS 4 (4C/8G/100G) ~$6.3; OVH VPS-1 (2C/4G/40G) $5.2–5.4; Hetzner CX33 (4C/8G/80G) ~$9.9; OVH VPS-2 (4C/8G/75G) $10; Hetzner CX43 (8C/16G/160G) ~$18.6; DigitalOcean 2C/4G $24; Linode 8GB $48.

    Warning — Hetzner capacity incident: active since 2026-06-26, restricting new cloud server creation; most CX/CAX plans show unavailable, and Hetzner raised prices twice in 2026 (CPX/CCX +113–176% in June). Treat Hetzner as great value only if you can get a slot; name Contabo/OVH as fallback.

  • Managed dev environments (zero-ops, fights always-on): GitHub Codespaces $0.18/h 2C/8G, $0.36/h 4C/16G, storage $0.07/GB-mo; 120 core-h/mo free (180 Pro); default idle timeout 30 min (max 240), auto-delete after 30 days stopped. Gitpod/Ona Core $20/mo. Coder OSS free (AGPL) self-hosted, needs Postgres + Docker/K8s + Terraform. AWS Cloud9 closed to new customers since 2024.
  • Rented GPU/CPU as dev env: rarely relevant. RunPod 2C/4G ~$43/mo, 4C/8G ~$86; RunPod RTX 3090 24 GB $0.50/h; Vast 3060 from $0.05–0.09/h; Lambda pricey. CPU-only dev here is 3–4× worse value than a VPS. RunPod storage keeps billing on stopped pods.
  • Home box: Mac mini M6 32 GB ~$1,499 (correction: the earlier $1,299 figure is the 24 GB config; 32 GB is ~$1,499, interpolated from Apple’s +$200 RAM / +$200 SSD ladder — verify in the configurator; memory non-upgradeable; M6 maxes at 32 GB, M5 Pro 64 GB at $1,699). Power: M4 idle 4–5 W; at $0.1834/kWh a mini costs ~$1–5/mo. Costs are capex + ops (UPS, ISP outage, no SLA, backups, patching, physical security).
  • Raspberry Pi-class: too weak. 8 GB Pi 5 $95 official / $168–175 resellers; the 8 GB RAM ceiling is fine for ssh+tmux but not for toolchains + a local model; no ECC; a $6–10 VPS beats it.
  • Laptop + mosh/tmux/rsync: the real baseline, unfairly underrated. mosh median keystroke latency 4.8 ms vs 503 ms SSH on 3G; <5 ms vs 273 ms MIT→Singapore. Free, zero-ops, zero blast radius. Gap: agent runs that outlive a sleep cycle.

Alternatives: Headscale (free self-hosted control plane, single-tailnet scope); plain WireGuard (fine for 2–3 static nodes); Cloudflare Tunnel (free tunnel since Jul 2026, Zero Trust free ≤50 users; good for HTTP, but TCP-oriented so mosh won’t traverse; adds a third party). Reject: ngrok (MITM on a key-holding box), port-forward + DDNS on a residential IP, plain public SSH. tmux is load-bearing (survives disconnect); mosh matters on lossy mobile links.

Workload fit & sizing

OpenCode is client/server: opencode serve on 127.0.0.1:4096, opencode attach <url>, opencode web, opencode pair. No VS Code needed.

Known bug #6063: the web frontend hardcodes localhost:4096 on remote-serve — pin a tested version.

Sizing: minimum 4 GB RAM / 2 vCPU / 40 GB disk; comfortable 8 GB RAM / 2–4 vCPU / 100–250 GB SSD. A GPU is not needed unless the box is also the inference host. If a local model is wanted: 14B Q4 ~8–9 GB, 32B Q4 ~18–19 GB — needs 32 GB Apple silicon; a GPU VPS starts ~$200/mo, so a ~$1,499 mini pays back in ~8 months.

Reliability & security

  • Cloud VPS: 99.9–99.99% SLA, contained blast radius, you patch. Managed: best uptime, but the container auto-deletes. Home box: no SLA, power + ISP dependent, high blast radius, you back up. Laptop-only: lowest blast radius.
  • Concrete security: no public SSH port (bind SSH to the tailscale interface only; PasswordAuthentication no, PermitRootLogin no); ed25519 keys, one per device; secrets are the real risk — prefer API keys staying on the laptop, or sops/age or 1Password CLI for persistent ones; never a long-lived LLM key in opencode.json; nightly restic to object storage + weekly snapshot; dotfiles repo + chezmoi/stow for a reproducible rebuild; treat the box as disposable, commit often.
  • Tailscale free covers solo use.

### Decisions
- **Primary recommendation: cheap VPS + Tailscale + mosh + tmux + OpenCode client/server.** Specifically a 4 vCPU / 8 GB / 80–160 GB box at $5–10/mo.
- **Selected primary candidates, in order:** Contabo Cloud VPS 10 (~$4.9/mo, 3C/8G/75 GB NVMe, 32 TB EU traffic) → OVH VPS-2 ($10/mo, 4C/8G/75 GB, unmetered, daily backup included) → Hetzner CX33 (~$9.9/mo, 4C/8G/80 GB, 20 TB) *contingent on availability*.
- **Do not recommend Hetzner as unconditional primary** — active capacity incident since 2026-06-26 restricting new cloud server creation; all CX/CAX currently shown unavailable.
- **Remote access stack (fixed):** Tailscale Personal (free, ≤6 users, unlimited user devices) as the private overlay → SSH key-only, password auth off, root login off, SSH bound to the tailnet interface only → tmux on the box (the load-bearing persistence layer) → mosh for interactive shells on lossy links → run the default `opencode serve` on `127.0.0.1:4096` and access it through SSH local port forwarding. If direct tailnet access is required, bind only to the VPS's tailnet interface address (never `0.0.0.0`) and configure the firewall to deny the service port on public interfaces and allow it only over the tailnet. Set `OPENCODE_SERVER_PASSWORD` as defense in depth; password authentication does not make public exposure safe or replace network restrictions.
- **Explicitly reject:** ngrok (MITM on a key-holding box), port-forward + DDNS on a residential IP, Cloudflare Tunnel as primary transport (TCP/HTTP-oriented; mosh cannot traverse the HTTPS path; fine as a fallback on locked-down networks), plain public SSH.
- **Headscale** is the named sovereignty alternative to Tailscale (free, self-hosted, BSD-3, but single-tailnet scope only).
- **OpenCode fit is native, not adapted:** verified client/server architecture (`opencode serve` on `127.0.0.1:4096` by default, `opencode attach`, `opencode web`, `opencode pair`). No VS Code required — this is a pure terminal path.
- **GPU is out of scope** for the dev box. Only add one if the same box becomes the inference host.
- **Sizing floor (hard requirement):** 8 GB RAM, 4 vCPU, 100 GB SSD. 4 GB/2 vCPU is the absolute floor and not recommended if a local model is ever added.

### Derived requirements
- R1: Box must survive client disconnect — tmux session on the box is mandatory, not optional.
- R2: Box must survive laptop sleep and Wi-Fi→cellular handoff — mosh (or mosh+tmux) for interactive use.
- R3: Zero inbound ports on the box. SSH reachable only over the tailnet.
- R4: Long-running agent tasks (≥20 min) must complete while the laptop is closed/asleep.
- R5: Repos must be pushed to a git remote after every meaningful step; the box is disposable by design.
- R6: Box configuration must be reproducible from a dotfiles repo in ≤30 min.
- R7: LLM/provider API keys must not live in committed config; use env vars or a secret store (1Password CLI / sops+age).
- R8: If a local model is desired, the box must be Apple silicon with ≥32 GB unified memory, OR a GPU VPS at ≥$200/mo — forcing a decision between those two, not a compromise.
- R9: Backups: nightly `restic` to provider object storage + a weekly provider snapshot. Git remote is the backup of record for source.
- R10: Patching: unattended security updates enabled on the VPS from day one.
- R11: Region must be chosen for latency from the user's actual location, not for price.

### Technical constraints
- OpenCode remote-serve has a known upstream bug where the frontend hardcodes `localhost:4096` (issue #6063) — the pinned OpenCode version must be validated before the workflow is relied upon.
- `OPENCODE_SERVER_PASSWORD` unset = documented-insecure web server. Set it as defense in depth for non-localhost exposure; it does not replace tailnet-only binding and firewall restrictions.
- shared-vCPU lines are acceptable (the workload is bursty, not sustained); do not pay for dedicated vCPU.
- Hetzner CAX (ARM) lines risk toolchain friction — prefer x86 unless verified.
- Codespaces (if used at all) is capped at a 240-minute idle timeout and 30-day stopped-retention; it cannot be an always-on primary.
- mosh requires UDP; it will not traverse a Cloudflare Tunnel HTTPS path.

### Cost constraints (verified)
- Target: **≤$15/mo all-in** for the VPS + Tailscale ($0) + backups (object storage, est. $1–2/mo for a small repo of snapshots).
- Estimated all-in primary: **$7–13/mo** (VPS $5–10 + Tailscale $0 + backup storage $1–2).
- Home-box alternative if chosen: $899 (16 GB) or ~$1,499 (32 GB) capex + $1–5/mo power at $0.1834/kWh; 13.7-year break-even vs a $9.9/mo VPS.
- Hard ceiling to reject: GPU VPS as a dev-only box (~$200+/mo, no justification without inference).

### Suggested acceptance criteria
1. From the MacBook Air on mobile Wi-Fi, `mosh` reconnects after a 5-minute network drop with no lost keystrokes.
2. An OpenCode task started via tmux on the box continues to completion after the laptop is closed for 30 minutes; reattaching shows the finished output.
3. `opencode attach` from the laptop, from a phone browser (`opencode web`), and from a second laptop all reach the same live session state.
4. Nmap/port scan of the box's public IP shows **no** open inbound ports other than what the OS requires; SSH is unreachable on the public IP.
5. `ssh root@<public-ip>` is refused; password auth is refused on all users.
6. Destroying and recreating the box from the dotfiles repo + a restic restore takes ≤30 minutes to a working OpenCode + Neovim + toolchain state.
7. Monthly cost, measured on the provider invoice after month one, is ≤$15.
8. A nightly `restic` run completes and a restore of a random file from 7 days prior succeeds.

### Risks that belong in the spec
- Hetzner capacity unavailability blocks the cheapest option at order time — spec must name a fallback provider.
- Mac mini 32 GB price is unverified interpolation (~$1,499); the $1,299/32 GB premise is likely wrong (that's 24 GB). Memory is non-upgradeable.
- Home box has no SLA and depends on residential power + ISP; a mid-task outage loses uncommitted work.
- OpenCode upstream bug may make `opencode attach` against a remote server unreliable on some versions.
- Secret sprawl on a persistent remote box is the highest-probability security failure mode; the spec must mandate a secret-store pattern, not env files.
- 2026 RAM/SSD price inflation means all hardware pricing in this report has a short shelf life — re-verify at purchase time.
